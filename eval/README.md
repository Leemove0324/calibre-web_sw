# 검색 품질 평가 (F9, #11)

중간보고서 "평가 수행 절차"를 실제로 돌리기 위한 파일 모음이다.
지표는 표 24(M1~M10), 조건은 계획서의 A~D를 따른다.

| 파일 | 내용 | 상태 |
|---|---|---|
| `samples_dev.csv` | 개발용 20권: 점수식·임계값 조정에만 쓴다 | **초안, 팀 확정 필요** |
| `samples_test.csv` | 평가용 50권: 5개 분야 × 10권. 최종 평가에만 쓴다 | **초안, 팀 확정 필요** |
| `gold.csv` | 정답표 (두 표본 70권) | **초안 채움(교보문고), 사람 검토 필요** — 아래 2절 |
| `results/raw/*.jsonl` | `collect.py`가 모은 검색 결과 원본 | 실행할 때 생김 |
| `results/*.per_query.csv`, `results/summary.csv` | `score.py`의 질의별 판정과 요약 | 실행할 때 생김 |

스크립트는 `scripts/eval/`에 있다 (`collect.py`, `score.py`, `evallib.py`).

## 1. 표본

- 평가용 50권은 문학 / 인문·사회 / 과학·IT / 아동·청소년 / 어려운 사례로 나누고, 분야마다 10권씩 둔다.
- 개발용 20권은 평가용과 **겹치지 않게** 고른다. 평가용으로 점수·임계값을 고치지 않는다 (중간보고서 805행).
- 열 구성:
  - `query`: 화면에서 입력할 검색어. 비우면 `title`을 그대로 쓴다.
  - 어려운 사례 중 몇 권은 같은 책을 다른 검색어로 다시 넣었다. 판 표기, 괄호, 띄어쓰기 오류가 섞인 검색어다 (예: T47~T49).
- 지금 목록은 제목·저자만 적은 **초안**이다. 팀에서 바꿀 책이 있으면 바꾼 뒤 `gold.csv`의 같은 id 줄도 맞춘다.

## 2. 정답표 (`gold.csv`) 작성 규칙

계획서에 따라 **두 사람이 따로** 작성하고, 서로 다르면 제3자가 정한다.

**지금 상태 (11/26):** 일정 때문에 70권 모두 AI(Claude)가 교보문고 검색 결과로 **초안**을 채웠다
(`checker_1` = `Claude(초안·교보문고)`).
- 사람이 각 줄을 열어 `isbn13`·`publisher`·`pubdate`를 확인하고 `checker_2`에 이름을 적는다.
- 틀리면 고치고 이유를 `note`에 적는다.
- `note`에 **[확인 필요]**가 붙은 11권은 판본 선택이 애매한 책이니 먼저 본다.
- 보고서에는 "AI 초안 + 사람 검토"로 작성 방식을 적는다 (계획서의 2인 독립 작성에서 변경).

| 열 | 쓰는 법 |
|---|---|
| `isbn13` | 정답 판본(대표 판)의 ISBN-13 (하이픈 없이). **비어 있으면 그 책은 채점에서 빠진다** |
| `isbn13_alt` | 함께 정답으로 인정할 **같은 책의 다른 판** ISBN-13 (공백으로 구분, 없으면 비움). 아래 기준 참고 |
| `title`, `authors` | 그 판본의 판권면·출판사 표기 그대로. 저자가 여럿이면 `&`로 구분 |
| `publisher` | 출판사 이름 (임프린트가 있으면 판권면 표기) |
| `pubdate` | 그 판본의 발행일. 아는 만큼만 적는다 (`2014-05-19` / `2014-05` / `2014`). 채점은 적은 자리수까지만 비교한다 |
| `checker_1`, `checker_2` | 확인한 사람 이름 |
| `evidence` | 확인한 곳: 교보문고·출판사 도서 페이지 URL, 판권면 사진 파일명 등 |
| `note` | 판본을 고른 이유, 제외한 판 |

- **정답 판본 정하기:** 판본이 여러 개인 책(번역서, 개정판, 리커버)은 "지금 판매 중인 일반판"을 정답으로 정한다.
  - 큰글자·청소년판·기념판·한정판·세트·초판본 복각판은 제외한다.
  - 같은 출판사의 개정판이 여러 개면 최신판을 고른다.
  - 고른 이유와 제외한 판의 ISBN을 `note`에 적는다.
- **채점 대상 제공처로 정답을 정하지 않는다.** 카카오, 국립중앙도서관, Google Books는 채점받는 쪽이다.
  - 교보문고(서점)나 출판사 페이지, 실물 판권면으로 확인한다.
  - 교보문고 검색 결과의 국내도서 항목에는 ISBN-13이 함께 있다 (상품의 `data-bid`).
- **검색어 변형 사례:** 같은 책을 다른 검색어로 넣은 줄(T47~T49)의 정답은 원래 책의 줄(T01·T14·T11)과 같다.
- **다른 판도 정답으로 인정 (`isbn13_alt`, PR #23 리뷰):** 맞는 책을 찾았는데 판만 다르다고 오답이 되지 않게 한다.
  - 넣는 것: 같은 출판사의 이전·이후 판, 기념판·특별판·보급판·양장판, 국내 창작물의 다른 출판사 판(글이 같음)
  - 넣지 않는 것: 큰글자·청소년판·그림책판(내용이 다름), 다른 출판사의 번역판(번역이 다름), 합본·세트
  - 다른 판으로 맞힌 경우 `match`가 `isbn_alt`로 남고, M4에서는 출판사·출간일을 비교하지 않는다(대표 판과 다를 수 있음).
- 정답표를 고치면 이미 측정한 조건도 다시 채점한다. `score.py`는 원본 결과를 다시 읽기만 하므로 빠르다.

## 3. 조건별 실행

| 조건 | 서버 코드 | 켤 제공처 (`--providers`) |
|---|---|---|
| A | 원본 0.6.27 (`git worktree add ../cond-A 0.6.27`) | `google,amazon,comicvine,douban,lubimyczytac` |
| B | F1 병합 후 `main` | A + `kakao,nlgo` |
| C | F2 병합 후 `main` | B와 같음 |
| D | F3 병합 후 `main` (기능 동결 버전) | B와 같음 |

- Google Scholar(`scholar`)는 학술 논문 검색이라 도서 평가에서 뺀다. 설치되는 `scholarly` 버전이 현재 의존성과 맞지 않아 불러오지도 못한다.
- A~D 모두 같은 PC, 같은 날, 같은 네트워크에서 측정한다. 응답 시간(M6)이 환경에 따라 달라지기 때문이다.

### 준비 (한 번)

```
pip install -r requirements.txt
pip install beautifulsoup4 html2text markdown2 python-dateutil   # amazon·douban·lubimyczytac 제공처용
```

### 한 조건 측정

```
# 1) 그 조건의 코드로 서버 실행 (시험용 서재 연결, 외부에서 접속 못 하게 127.0.0.1)
python cps.py -i 127.0.0.1 -p <app.db 경로>

# 2) 다른 창에서 수집 (키는 환경 변수로만)
$env:KAKAO_REST_API_KEY = Read-Host "Kakao key"      # B 이후, 서버를 띄우기 전에 설정
$env:EVAL_SERVER_COMMIT = git -C <서버 폴더> rev-parse --short HEAD
python scripts/eval/collect.py --condition A --set test --providers google,amazon,comicvine,douban,lubimyczytac --check-covers

# 3) 채점
python scripts/eval/score.py eval/results/raw/A_test_*.jsonl
```

- `collect.py`는 화면의 "메타데이터 가져오기"와 같은 경로(`POST /metadata/search`)로 검색한다. 그래서 조건별로 코드가 달라도 같은 스크립트를 쓴다.
- `--providers`에 적은 제공처만 켜고 나머지는 끈다. 실행이 끝나면 원래대로 되돌린다.
- `--only T01,T02`로 몇 권만 시험해 볼 수 있다.
- `--pause`(기본 0.5초)는 질의 사이 쉬는 시간이다. 제공처 호출 제한(Google 429 등)에 대비한 것이다.

## 4. 지표 계산 (`scripts/eval/evallib.py`)

| 지표 | 계산 | 목표 |
|---|---|---|
| M1 1순위 적중률 | 1순위 결과가 정답 도서인 질의 / 전체 | ≥ 90% |
| M2 상위 5위 재현율 | 상위 5개 안에 정답 도서가 있는 질의 / 전체 | ≥ 95% |
| M3 필드 완성도 | 1순위 결과의 7개 항목 중 채워진 수의 평균 | ≥ 6.0 |
| M4 필드 정확도 | 1순위가 정답일 때, 채워진 제목·저자·출판사·출간일·ISBN 중 정답표와 맞는 비율 | ≥ 95% |
| M5 표지 확보율 | 1순위 결과에 쓸 수 있는 표지가 있는 질의 / 전체. `--check-covers`면 실제로 이미지가 받아지는지 확인 | ≥ 95% |
| M6 응답 시간 | 질의별 응답 시간의 p95 (최근접 순위) | ≤ 5초 |

- **정답 도서 판정:** 결과의 ISBN-13이 정답표(`isbn13`) 또는 같은 책의 다른 판(`isbn13_alt`)과 같으면 정답이다.
  - 결과에 ISBN이 없을 때만 정규화한 제목이 같고 저자가 한 명 이상 겹치면 정답으로 본다. 이런 경우는 `per_query.csv`의 `match` 열에 `title_author`로 남고, 요약에도 개수가 나온다.
  - ISBN이 있는데 두 목록 어디에도 없으면 정답이 아니다 (인정하지 않은 판이거나 다른 책).
- **M5:** 표지를 실제로 저장하는지는 F6 일괄 작업(M8)에서 본다. 여기서는 검색 결과 단계의 확보율이다.
- **M7~M10은 다른 방법으로 측정한다.**
  - M7: F4 지연 주입 시험
  - M8: F6 50권 일괄 처리
  - M9: F7 되돌리기
  - M10: CI의 커버리지 검사 (`scripts/check_coverage.py`)

## 5. 기록

- `results/raw/`의 원본은 지우지 않고 커밋한다. 채점 규칙이나 정답표가 바뀌어도 다시 채점할 수 있게 하기 위해서다.
  - 각 원본 옆의 `.meta.json`에 조건, 제공처, 시각, 서버 커밋이 남는다.
- 동결 뒤 오류를 고쳐 결과가 바뀌면, 고친 버전으로 다시 측정한다. 이전 값과 섞지 않는다 (중간보고서 805행).
